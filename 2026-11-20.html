AIが道具を「必要な分だけ」取り出す時代へ／AIの頭の中を見張る安全装置／nginxの重い脆弱性

主要ニュース

Gemini APIに「Tool Retrieval」が登場、AIエージェントが道具を必要なときだけ読み込む

GoogleはGemini APIに、使う可能性のある道具（関数）の詳しい説明を後回しにし、必要になった時点でだけ読み込むTool Retrievalを加えた。tool_searchを追加し、道具にdefer_loadingを指定すると、モデルには名前と説明だけが見え、必要なときに同じリクエストの中で詳しい定義が読み込まれる。検索はサーバー側でもクライアント側でも動かせ、MCPサーバーにも使える。Gemini 3.6以降のモデルを対象に、Interactions APIでプレビュー提供。

何が変わるか：エージェントがつなぐ道具が増えるほど、入力トークンの費用と道具の選び間違いが増えるという壁を低くする。ただし固定の追加トークンがかかり、一度読み込んだ定義は会話の間ずっと課金されるため、効果は自社の利用状況で確かめる必要がある。

出典：Introducing Tool Retrieval in the Gemini API

inclusionAIが「SingProbe」を公開、DeepSeek-V4.1-FlashとLing-3.1-flashの内部を読んで危険を見張る

Ant GroupのAI研究組織inclusionAIが、Hugging FaceにDeepSeek-V4.1-Flash-1017向けとLing-3.1-flash-1019向けのSingProbeを公開した。モデル内部の3つの層の隠れ状態を読み、生成中のトークンごとに質問の意図、回答の危険性、ハルシネーションの危険を点数にする約1000万パラメータ（Ling向けは約800万）の小さなプローブで、ライセンスはMIT。モデルカードでは、専用のガードレールモデルと同等以上の成績としているが、ハルシネーション検出はやや下回り、遅延への影響は書かれていない。

何が変わるか：重みが公開されているからこそ作れる「内側からの」安全対策で、オープンウェイトの使い道が性能競争から安全な運用の工夫へ広がっていることを示す。自社環境でモデルを動かす企業にとって、ガードレールの新しい選択肢になる。

出典：inclusionAI/DeepSeek-V4.1-Flash-1017-singprobe

nginxのHTTP/2に乗っ取りにつながる脆弱性（CVE-2026-123007）、攻撃コードは公開済み

nginxのHTTP/2のフロー制御の計算に整数アンダーフローがあり、認証なしでワーカー権限のコード実行につながる。1.9.5（2015年）以降が影響を受け、1.31.9と1.30.7で修正された。StepSecurityは、reloadではなく再起動が必要なこと、バージョン表示ではなくパッケージで修正を確かめること、コンテナはイメージから作り直すこと、保守が終わったingress-nginxではHTTP/2を止めることを勧めている。

何が変わるか：攻撃コードが出回っており、HTTP/2を有効にしたnginxは非常に多い。「更新したつもり」で古いプログラムが動き続ける落とし穴が多いため、再起動とパッケージでの確認まで終えることが大事。

出典：nginx2root (CVE-2026-123007): HTTP/2 Flaw Lets Attackers Run Code on Unpatched nginx Servers

偶然の出会い

同じモデルでも段取りで差が出る、SnykがAIによる脆弱性探しの「ハーネス」を比較

Snykは試験中のEvo Code Scanning Agentを、同じモデル・同じ費用の条件でClaude SecurityやCodex Securityと比べた。弱点の場所がわかっている14のアプリで、Evoはすべてのアプリで多くの弱点を見つけたが、正確さでは相手のほうが上だった。最もよい結果でも約3分の1は見逃され、それぞれの道具が相手の見逃した弱点を見つけていた。

何が変わるか：AIの道具はモデルの性能だけでなく、調べさせる段取り（ハーネス）で結果が大きく変わる。一つの道具に頼らず、ほかの対策と重ねて使うべきだと分かる。

出典：Why the Harness Matters: Early Lessons From the Evo Code Scanning Agent Preview
